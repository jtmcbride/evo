**M7 sensor interventions and matched replay**

Create or load an experiment, select a controller/trial, and pause playback at the desired tick. In **Sensor intervention**, choose one of the 20 inputs and run a matched comparison. The workbench shows both sampled paths, terminal outcomes, food, distance, contact time, survival, remaining energy, and the number of overlapping decisions with different motor commands. Expand the observations table for all raw/effective readings at the first affected decision.

At tick 17, the held command from decision 15 continues normally. Both forks advance to the pre-decision state at tick 18; the mask first affects decision 18. At a decision boundary such as tick 18, the mask applies immediately to that decision. The UI reports both requested and actual ticks. Terminal episodes and requests with no remaining decision are rejected without modifying playback.

`ComparisonRunner` owns a copy of the requested `EpisodeCheckpoint`, aligns it by at most two physics ticks, then restores two private runners from the exact same checkpoint. This preserves pose, held commands, velocities, energy, remaining food, accumulated contact, measurements, and controller random state. The original playback is left at the requested tick. Training uses its own experiment runner and receives no mask or modified parameters.

The version-1 `sensorMask` variant identifies its channel and start tick. At each subsequent decision, sensing runs normally, the raw vector is recorded, and exactly one effective input is replaced with positive zero before controller inference. The body and sensor geometry are unchanged. Neural weights are copied unchanged. Raw inputs, effective inputs, hidden activations, and outputs are present in masked decision traces and survive episode checkpoint restore.

Unmodified evaluation identities and engine behavior remain unchanged. The masked result's evaluation specification includes the intervention, producing a distinct specification hash while retaining the original controller parameter hash. This is an evaluation variant, never a mutation or a new training objective. The comparison ID includes the exact source checkpoint and intervention. Comparing/replaying the same saved source is idempotent; changing the source tick or channel creates another comparison.

The paired paths start at the aligned decision state, sample every three physics ticks, and include each terminal endpoint. Outcome totals include the common episode prefix. Action differences compare the two actual motor output pairs at shared decision ticks while both arms remain alive; they do not count later decisions after one arm terminates. A zero raw input can produce no immediate difference. Later differences include the effects of divergent motion and observations. These are controller/scenario-specific observations, not universal labels for sensor or neuron function.

Each worker pump gives comparison work an approximately 2 ms share of its existing soft 8 ms budget, with checks between groups of 16 paired ticks. Playback and training still receive work within the slice. Worker reinitialization, disposal, request cancellation, and request timeouts settle outstanding comparison requests. No live buffer is transferred or detached.

Comparisons save independently in IndexedDB and restore when the experiment is loaded. **Replay saved comparison** runs both arms again from the saved source and checks exact outcomes, first-decision traces, and paths against the existing record. A mismatch is reported without overwriting the original. Playback selection, current training population, and display preferences are not used to reconstruct that saved source.

Database schema 2 adds an immutable checksummed comparison table to the M6 schema. The population head/revision remains independent. Load merges numerical checkpoints with comparison rows; later generation saves cannot erase them. Numerical checkpoint payloads omit trajectories so training does not rewrite them each generation. A failed comparison save retains its record in memory, exposes **Retry comparison save**, and includes it in export without blocking training. An experiment retains up to 32 comparison records; additional distinct comparisons require a new experiment. Records are not silently evicted.

`.evolab` archive version 2 includes comparison sources/results/paths and external little-endian parameter blobs even for controllers absent from the current population or retained champions. The reader still accepts M6 version-1 archives and supplies an empty comparison list. Existing database heads/checksums are not rewritten during migration. Session payload version 1 gains the optional bounded comparison list; archive, database, intervention, and numerical engine versions have distinct meanings. Existing archive size and expansion limits continue to apply.

Exact replay is verified within the pinned Chromium runtime. Runtime provenance still accompanies portable sessions; importing in a different browser/device does not establish bit-identical math. A mismatching rerun preserves the original record. A direct Node 24 rerun of a Chromium-generated comparison showed differences around 1e-16 in activations and 1e-14 in path coordinates/distance. Tests therefore check archive data preservation across hosts and numerical equality within each supported runtime, without treating approximate agreement as exact replay. The workbench does not aggregate these exploratory interventions into a held-out evaluation or scientific claim. M9 now adds neuron clamps, parent-weight restoration, and branching; see the extended guide below.
