**M8 retained lineage and parent/child replay**

Every saved population now retains its births and recorded generation trials, including descendants that later leave the population. Elite copies keep their original identity; surviving for several generations does not create another birth. Founders and immigrants remain separate origins. A new mutated child retains its actual parent ID, mutation seed, changed parameter indices, and exact Float32 new values.

In **Controller lineage**, follow the selected controller, inspect an ancestor or child, or find any retained controller by its ID. Browsing the family does not change the arena. **Replay retained controller** opens its original recorded trials when available; the Trial selector switches among them. If that birth has no recorded evaluation, replay uses the selected trial map and labels it as a new evaluation. A retained champion snapshot can supply an older original trial even when the surrounding generation history is incomplete. The UI identifies the generation of the available trials.

The explorer returns at most 30 ancestors and 20 children per page. Older ancestors and child pagination keep large families bounded. The mutation table shows the original parameter index, connection or bias, parent value, and child value without rounding the recorded Float32 values. A missing parent remains explicitly unavailable; it is not relabeled as a founder. Missing lookups preserve the previously inspected controller.

**Compare parent and child** runs both frozen controllers from tick zero on an explicitly shared suite: either the selected trial map or the child's recorded trial maps. Both arms have identical scenario configuration, initial body, energy, food, and obstacles on each map. Their weights remain independent. The suite ID hashes the ordered scenario hashes; each result also references its own controller identity and parameter hash. The view reports mean food, distance, contact time, and survival, with selectable paired trajectories. Source selection scores are never substituted for these new evaluations. This is an exploratory comparison, not a held-out test or a claim about neuron function. Its result stays in the current view; retained weights and original maps allow rerunning it after import/reload.

`retainGenome` and `reconstructGenome` define the pure lineage module. Sparse mutations use their recorded index/new-value patches. Founders, immigrants, births with more than 64 changed parameters, births at a multiple of ten generations, and births that would exceed 16 patch edges use full anchors. A child whose parent is unavailable is retained as a full anchor with its real parent reference intact. Reconstruction copies an anchor, applies exact Float32 values, and verifies parameter hashes, identity, parent age, patch indices, and depth. It does not regenerate weights from random seeds. Full anchors with retained parents are also checked against their mutation patches.

Database schema 3 adds checksummed lineage records and coverage metadata. Full anchors refer to deduplicated binary Float32 blobs; they do not repeat byte arrays inside JSON. New sparse births do not add full parameter blobs. Numerical recovery checkpoints remain self-contained, and the head plus every tenth population checkpoint remain retained. Generation metadata, membership, scenarios, all genome/trial measurements, validation trials, births, and the next checkpoint commit atomically before the worker receives acknowledgment. A failed checkpoint write rolls back the new lineage too. Matching commit retries are idempotent, and stale population writers remain blocked.

M6/M7 databases are backfilled lazily from their existing birth metadata and full parameter blobs when lineage is first requested or training continues. Backfill verifies parameter hashes and actual patches and leaves saved numerical checkpoints and their checksums intact. Existing legacy blobs are preserved; migration does not run speculative global garbage collection. All new writes use the sparse representation. An experiment's coverage starts at the earliest continuous sequence of complete retained generation records. A checkpoint-only import begins coverage at its imported population; it cannot recover descendants or trials absent from that file.

**Export checkpoint** remains the version-2 population backup with retained champion snapshots, the current bookmark, sensor comparisons, and partial ancestry. **Export full lineage** emits version 3 with every retained birth, reconstruction anchor/patch, generation membership, original scenario, training trial, and validation result. Pause training and save the population before a full export. Both export modes exclude an active partial generation. A full-lineage archive of a checkpoint-only import is still marked partial; exporting cannot invent its earlier history. Imports always create a separate local experiment and publish no partial records on failure.

Version-3 archives add `lineage.json` and, when needed, a packed `lineage-parameters.f32` file. The latter contains deduplicated 1,112-byte little-endian parameter blocks referenced by aligned offsets and parameter hashes. Parameters already present in checkpoint files are reused. This avoids one ZIP entry per historical anchor. The manifest distinguishes checkpoint/lineage and partial/complete coverage. Import checks file hashes, offsets, parameter hashes, patch reconstruction, ancestry age/order, source references, complete generation coverage, original evaluation specifications, totals, generation commit identities, and agreement with the archived current population. Older archive versions 1 and 2 remain readable.

The existing limits remain: 32 MiB compressed, 64 MiB total expanded, 16 MiB session JSON, 128 KiB manifest, and 1,024 entries. The lineage record and packed anchors each remain within the total expanded limit; a bundle also permits at most 100,000 births and 10,000 complete generation records. An oversized export reports failure without deleting local history. Long-run byte size, browser eviction, and broader-device performance still require the M10 release work. No records are silently evicted to fit an archive.

Only the inspected family page and comparison enter React state. A synchronous request records the desired controller before loading, so a generation save cannot redirect an in-flight lookup to an older family. Ancestor playback marks controls busy before switching its trial. Parent/child work shares the worker's bounded comparison scheduling and cancellation, without changing experiment buffers or training identities. Runtime provenance and same-runtime numerical replay limits still apply; Node and Chromium are not assumed to have bit-identical transcendental math.
