**M9 controlled branches and extended interventions**

Open **Branches & common evaluations**, expand **Create a branch**, and review its configuration diff before creating it. Branching requires a saved `readyToEvaluate` population, paused training, and no pending comparison saves. Finish an active generation before branching. The UI exposes food/obstacle counts, body radius, sensor range, maximum speed, mutation probability, and mutation magnitude. The controller topology remains 20–12–2.

A branch copies the current generation's logical membership and immutable genome identities. Its configuration and experiment identity are new; its generation index and initialization/training/evolution/validation roots are preserved. Existing elite identities stay unchanged. Newly born descendants and immigrants use the branch's experiment ID, while selection ties, tournaments, mutation streams, and immigrant initialization use the preserved roots and generation/slot keys. An otherwise identical fork therefore produces identical numerical results and offspring parameters with separate birth IDs. Environment changes can transform the same schedule seeds into different realized maps; those maps are recorded rather than assumed identical.

Creation reads the saved source checkpoint and retained lineage, records a source checkpoint hash, source definition, source name/local reference, exact membership IDs/parameter hashes, and explicit before/after settings. The source revision is checked again inside the transaction that publishes the new experiment and active pointer. Source population/history/checkpoint bytes are unchanged. A failed or stale fork publishes no partial experiment. Nested branches retain a bounded provenance chain, shown in the panel; up to 16 branch points are supported. Imported files retain the captured provenance even when the original local source save is unavailable.

Each retained generation can carry its actual experiment definition. This preserves source records under their original world/evolution settings and commit identity when a branch changes configuration. Full archives retain the inherited ancestral closure, unsuccessful descendants, source membership, and original trials. A population-only checkpoint remains explicitly partial; it cannot restore ancestors absent from the file. History labels inherited source scores, and environment-changing branch histories direct comparisons to common evaluation suites.

Train at least one generation in each experiment before selecting **Compare training-selected champions**. The current branch's inherited source champion is excluded until the branch has selected its own champion. Choose a saved reference experiment and one to eight maps per environment. The result is a full two-controller × two-environment matrix: both controllers on the source environment suite, and both on the branch environment suite. Each row labels the experiment, genome, and actual generation of training selection. Different training budgets remain visible.

Matrix maps use a separate deterministic comparison schedule derived from the recorded fork checkpoint, never a held-out test suite. The source and branch columns use the same seed list transformed by their respective world configurations. Each column's suite ID hashes its ordered realized scenario hashes, and each cell's newly computed trials reference that suite and controller. Source training scores are never substituted for evaluations. The panel shows mean food, contact time, survival, and per-map food results. These are exploratory comparisons, not a generalization claim or a guarantee of specialization.

Matrices save independently of population revisions. A numerical generation save cannot erase them; a matrix save cannot advance training. Up to eight immutable matrices are retained per experiment. Failed matrix saves keep exportable in-memory records and offer a separate retry. **Replay saved matrix** re-evaluates all four cells from the stored controller weights and actual scenarios, including after import into a fresh browser context without the original source experiment. Exact mismatch reporting preserves the original record. A new evaluation after further training produces a new matrix; saved rows do not silently update.

**Sensor & brain interventions** adds two options to the existing matched replay:

- **Hidden neuron clamp** chooses H0–H11 and an activation in [−1, 1]. At the next decision, inference computes the normal post-tanh hidden vector, records it, replaces exactly the selected activation, then computes motor outputs. Raw and effective hidden activations are shown separately. Inputs and inherited parameters remain unchanged.
- **Restore parent weight** chooses an index from the 278 neural parameters. The repository reconstructs the selected controller's actual parent. The runner verifies the child/parent relationship and parameter hashes, then substitutes the parent's exact Float32 value in a private evaluation buffer from the next decision onward. It does not approximate the value from a mutation seed or change the saved child genome. Parent and child snapshots accompany the result for portable replay; available ancestry in those snapshots can enrich a checkpoint import.

Both operations use the same exact pre-decision forks as sensor masking. A request at tick 17 preserves the held action until decision 18. Body state, remaining food, energy, contact accumulation, and controller state are matched. Each modified result has a separate evaluation specification; the original controller version still identifies its inherited weights. Modified hidden traces and intervention definitions survive arbitrary-tick episode restore. New intervention identities preserve signed-zero values without changing legacy unmodified/sensor-mask evaluation hashes.

The live selected trial and numerical training runner are independent of all comparison jobs. The worker uses the existing bounded comparison slice, rejects stale experiment epochs, and settles replacement/cancellation/disposal requests. All supported comparison types share one job slot, so UI controls prevent overlapping comparison requests. Archive compression remains on a separate worker.

Database schema 4 adds checksummed matrix records while preserving existing numerical heads and lineage tables. Archive version 4 adds branch provenance, per-generation definitions, matrix snapshots, and extended intervention records. Parameter vectors use the existing explicit little-endian binary files and packed lineage anchors, including restoration and matrix-only controllers. Readers still accept versions 1–3. Plain population backups without M9 fields remain version 2; legacy lineage bundles without generation definitions remain version 3. Archive limits stay at 32 MiB compressed, 64 MiB expanded, 16 MiB session JSON, 128 KiB manifest, and 1,024 entries. Oversized exports fail without deleting saved data.

Same-runtime exactness remains the contract. Browser descriptors are retained as provenance; Node and different browsers/devices are not assumed to produce identical transcendental math. Imported records can be continued under supported semantics, while an exact replay mismatch leaves their original measurements intact.
